# Value mappings

A value mapping says which universal concept each value stored in a dataset is. It lives in the
project because the values belong to the dataset: Chinook stores a country as a name, another
database may store a code or a numeric id.

- [chinook.country-values.json](chinook.country-values.json): the 24 distinct country values of
  Chinook (`Customer.Country`, `Invoice.BillingCountry`, `Employee.Country`) mapped to the
  `country` concept of [`meaninggraph/core`](https://github.com/meaninggraph/core) at the commit
  pinned in the file.

## Format

One JSON file per mapping: a header, then `rows`, **one row per value**, so the rows can be read
as a reference record set (a validator can check that a field's value is one of the `value`s).

```json
{
  "id": "chinook-country-values",
  "type": "value-mapping",
  "concept": "meaning://github.com/meaninggraph/core/country?ref=<40-character commit>",
  "codeSystem": {"name": "ISO 3166-1 alpha-2", "key": "alpha2", "case": "upper"},
  "valueType": "string",
  "match": "labels",
  "covers": [{"source": "chinook", "collection": "Invoice", "column": "BillingCountry"}, "..."],
  "columns": [{"name": "value", "type": "string"}, {"name": "code", "type": "string"}, {"name": "concept", "type": "string"}],
  "generated": {"by": "node scripts/build-country-mapping.mjs", "from": ["..."]},
  "licence": "CC0-1.0",
  "rows": [
    {"value": "USA", "code": "US", "concept": "meaning://github.com/meaninggraph/core/country?ref=<commit>"},
    {"value": "Czech Republic", "code": "CZ", "concept": "meaning://github.com/meaninggraph/core/country?ref=<commit>"}
  ]
}
```

| Field | Meaning |
|---|---|
| `covers` | the dataset fields whose values the mapping covers; every distinct value of every one of them has a row |
| `concept` | the universal concept, `meaning://` address with the 40-character commit (never a branch or tag) |
| `valueType` | `string` or `integer`: the type of `value`. A dataset with a `CountryId` column maps its ids with `valueType: integer`, `match: codes.numeric` and rows such as `{"value": 372, "code": "IE", ...}`: the same rows, only `value` differs. A code with a leading zero (Argentina is `032`) is compared as a string, so such a column must hold strings |
| `match` | how stored values were matched to core's values: `labels` (a label or alias in any language, ignoring case) or `codes.<code>` (that code, exactly), the two modes of core's `FORMAT.md` |
| `code`, `codeSystem` | the code of the country, in the system the header names |

### Alpha-2

`code` is the **ISO 3166-1 alpha-2** code (`US`, `CZ`), for three reasons. It is the key of core's
country values (the lowercase code, `us`), so a row's code and the concept's value id are the same
thing. It is the key the project's geo data uses (`countries` and `population_wb` are keyed by the
lowercase alpha-2 code), so the join table needs no translation. And it is the shortest code that
is unambiguous. Core lists the alpha-3 and numeric codes of every country as well; a mapping for
another system can name one of them in `codeSystem.key`.

## Generated, not written

The file is generated by [`scripts/build-country-mapping.mjs`](../scripts/build-country-mapping.mjs)
from the pinned Chinook file and the pinned core commit, together with the records of
`data/geo/country_aliases` that the saved query joins. See the README at the repository root for
the commands and what CI checks. Licence: CC0 1.0 like the rest of the project's files; core is
CC0 too and Chinook's country names are plain facts, so the file carries no third-party terms.
